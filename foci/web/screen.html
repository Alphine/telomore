IDR plate mode

Choose one plate of the genome-wide 53BP1 screen (Doil et al. 2009). Your browser downloads that plate's wells from our cache, counts nuclei and foci with the Foci Lab engine, and lines the result up with the authors' own per-well numbers. Our server never runs the analysis; it only hands out images.

Open question: which annotation row belongs to which image?

The image grid of a plate and the authors' table number the wells differently. Matching them by well name (image A2 with row A2) and matching them by the annotation's Well Number with the image grid counted column by column (A1, B1, … L1, A2, …) give different pairs, and so different agreement. Experiment L2 found that the second rule agrees better with the authors' cell counts on plate 7-14, but that is indirect evidence; the curators or the authors would have to confirm which is right, and this page does not claim either. Both pairings are therefore shown side by side everywhere. See docs/EXPERIMENT_PROTOCOL.md §15.4.

Read this first.
  • The counter is exploratory and not validated against manual counts. A low or high correlation with the authors' numbers does not by itself say which side is wrong.
  • 53BP1 foci mark DNA double-strand breaks anywhere in the genome; they are not telomere-specific.
  • Images come from the public Image Data Resource (idr0010, CC BY 4.0) through a cache on this site; an image is fetched from IDR once and then served from the cache. Nothing you do here uploads anything.

What this will cost

  • image requests ( wells × 2 channels: DNA and 53BP1). Each image is fetched from IDR once and then cached on our server.
  • Per visitor the server allows . If it says “slow down” this page waits and tries again; it never retries forever.
  • Hard cap for this browser tab: image requests (used so far: ). One plate at a time.
  • Memory stays small: each well is analysed as it arrives and only its counts are kept.
Engine parameters (optional)

Defaults come from the engine. To change some, enter a JSON object such as {"min_height": 14}; it is merged over the defaults and recorded in the provenance export.
